# 项目适配

首次进入项目，或验证渠道、真源、环境边界变化时读取。把所需选择写进活动批次，不要求项目安装额外工具或重构既有文档体系。

## 真源与规模

从项目约定、当前入口和原任务中定位以下内容，批次保存引用及本批特有决定：

| 内容 | 优先复用 |
| --- | --- |
| 产品规则、架构和设计 | 原规格、有效设计记录、现有产品约束和 ADR |
| 任务状态、依赖和认领 | 原 tracker；无 tracker 时使用已有任务清单，避免创建多个状态源 |
| 批次范围、批准、阶段、证据和恢复点 | 一份活动批次记录 |
| 部署、配置、运行与环境验收事实 | 原操作记录、环境台账或平台事实；批次链接对应版本/条目 |
| 源码及产物 | 实际工作目录、提交、构建及原始验证结果 |

如果当前只有已批准任务，直接消费它们；不为使用本技能重写规格或重拆任务。没有 tracker 的小项目可在批次列任务顺序，但不再维护第二份同义状态表。

短批次也要可恢复：目标/排除项、Status、当前与批准版本及来源、验收项、实际证据、失败记录、下一步足够时，可以省掉独立的映射或风险表。多仓、外部系统或人工验收较多时，再展开模板的对应栏目。

## 按交付物选择验收

以下是选择依据，不是所有项目都必须执行的清单。最终以批准的验收矩阵为准。

| 交付物 | 常见必要证据 | 何时增加真实环境或人工验收 |
| --- | --- | --- |
| Web / 桌面 UI | 相关逻辑与构建检查、普通运行中的完整用户路径及适用视觉证据 | 浏览器/系统差异、交互判断或外部服务是验收的一部分 |
| 移动应用 | 相关测试与构建、普通应用路径；按需用模拟器 | 硬件、权限、推送、后台或设备行为需要验证；设备型号及构建需绑定 |
| CLI | 实际命令的输入、输出、退出码、文件或进程副作用及错误路径 | 交互终端、目标 OS、安装方式或真实工具链决定结果 |
| 库 / SDK | 公共接口行为、消费者调用、兼容性及适用类型/构建检查 | 运行时或依赖版本矩阵、真实外部契约构成验收要求 |
| 后端 / API | 逻辑与契约、数据一致性、关键成功/错误路径 | 真实路由、身份认证或跨服务交互不能由隔离测试证明 |
| 基础设施 / 重构 | 预期变化或行为不变的证据、目标配置/产物差异及适用回归 | 实际环境语义、迁移和回退能力需要验证；副作用须在已有授权内 |

没有视觉目标就不要求设计稿；没有接口变更就不要求 API 表。每个适用映射都记录实际标识、版本或读取日期；“存在截图/契约”不能自动等同已审核或已部署。

测试层级由影响面决定：先针对性检查，公共边界变更再扩大，集成节点执行必要完整回归。需要某设备或外部环境但无法获得时，相关项记阻塞；可以完成无关本地工作，但不能宣称整个批次通过。

## 环境、资源与并行执行

涉及共享或远程环境时，将以下内容纳入计划：

1. **当前基线**：实际候选、配置、路由及已验收能力；复用既有环境真源。
2. **变更边界**：目标环境、执行者、允许动作、费用/次数限制与回退条件。单个批次的预算用尽不自动授权关闭其他已验收能力。
3. **保留与清理**：长期依赖和临时资源的具体身份、引用关系、清理条件及清理后检查。凭名称或创建日期不能判定可删除。

已有保留策略就遵守它。没有策略时，在本批计划明确生命周期；一次性预览可以按批准计划撤销，长期共享环境应保留约定能力及所需依赖。收尾不默认撤销仍被使用的凭据、清空账号或降低已验收能力。

仅清理已解除依赖、身份核对一致且处于授权范围内的资源。清理或回退后检查承诺保留的能力；必要条件缺失时记录阻塞，不把环境退化视作成功收口。

并行工作无需成为默认。已有明确授权且任务可隔离时，登记每项工作目录、负责人、基线、集成目标与回收责任。共享集成和环境写入串行。功能验收与 Git/资源生命周期分别记账。

## 变更与证据失效

- 普通实现修复：当前计划版本不变，重验受影响项。
- 实质范围、规则或验收变更：计划升版，保留旧批准来源，新版本确认后继续相关实施。
- 源码、配置、契约或环境漂移：对照证据适用范围，只复用未受影响的结果；无法确认时补验或记录未知。
- 人工通过后的产物变化：重新绑定交付物，必要时补充人工验收；旧结果原样保留。
- 工具或渠道不可用：说明覆盖缺口与可行替代。替代能否满足原验收按其证明能力判断，改变必要标准则走计划变更。
